# Phase 4 contract

The user explicitly approved: INR invoices with tenant-sequential numbering, manual prices and explicit per-line tax percentages, half-up paise rounding; cash and manually recorded UPI/card receipts, no overpayment, owner-only void of unpaid invoices, no refunds/discounts/paid-invoice corrections. Pharmacy uses integer units, exact medicine/strength/route and batch/date metadata, FEFO, full dispensing only with prescribed quantities, prescribing-doctor approval of exact substitutions, and Asia/Kolkata expiry dates. Lab observations are manual, with separate technician PIN sign-off, requesting-doctor verification and explicit LAB release. Cash close uses opening float plus cash receipts, a reason for variance and OWNER review.

New code extends the existing tenant-scoped repositories, transaction retry ledger and immutable clinical records. No external gateway charges, automatic tax-law selection, drug-equivalence claim or automated lab interpretation is introduced.

## Invoice / cash API (all /api/v1)

GET/POST /invoices; GET/PATCH /invoices/:id (draft only, expected_version); POST /invoices/:id/issue (expected_version); POST /invoices/:id/void (OWNER, expected_version, reason, fresh mfa_proof (authenticator or recovery code)); POST /invoices/:id/payments (RECEPTIONIST, amount decimal INR, CASH/UPI/CARD, noncash external reference); GET /invoices/:id/payments. POST financial commands require Idempotency-Key; draft PATCH uses expected_version. Lines require description, positive integer quantity, decimal unit_price and explicit tax_percent; totals use integer paise. Issue assigns INV-000001-style tenant sequence. Issued content is immutable. Zero-balance invoices are PAID. Paid invoices cannot be voided. CASH receipts require the receptionist's OPEN cash session.

GET /cash/sessions retains own/OWNER scope. POST /cash/sessions/:id/close requires counted cash and expected version; the server snapshots opening + cash receipts, calculates variance, and requires a reason if nonzero. POST /cash/sessions/:id/review is OWNER-only with a reason/review note and fresh MFA. Closing serializes against cash receipt recording. Closed sessions accept no further receipts. Review never edits payment or movement history.

## Pharmacy API

GET/POST /pharmacy/batches; POST /pharmacy/batches/:id/adjustments records a reasoned stock correction rather than client-selected arbitrary allocation. Batch metadata: exact medicine, strength, route, unit label, batch number, quantity and YYYY-MM-DD expiry. Batches expire after their stated Asia/Kolkata calendar date. Metadata is immutable once created. Adjustments are append-only and stock cannot go negative.

GET /pharmacy/prescriptions lists latest signed revisions only. POST /prescriptions/:id/substitutions requests an exact alternative per line with a reason; POST /pharmacy/substitutions/:id/approve is the prescribing DOCTOR with password confirmation. POST /prescriptions/:id/dispense allocates full prescribed quantities automatically by expiry, then batch ID, rejects expired/insufficient stock and records immutable allocations. A verified PHARMACIST is required for all stock/dispense mutations. Generic alternatives retain prescribed strength and route; any dose conversion requires a new prescription. One dispense per encounter; earlier signed revisions cannot be dispensed after a newer draft/signed revision exists. A new correction revision is blocked after dispensing so existing fulfillment cannot be silently rewritten; new prescribing then needs a new encounter. This is administrative workflow protection, not a medical-equivalence engine.

## Laboratory API

POST /lab/orders/:id/collect (state=COLLECTED, expected_version) transitions ORDERED → COLLECTED. POST /lab/orders/:id/results creates a RESULT_DRAFT or a reasoned new correction revision; GET /lab/orders/:id/results lists authorized history. PATCH /lab/results/:id updates draft-only observations/version. POST /lab/results/:id/sign requires LAB's separate sign-off PIN. POST /lab/results/:id/verify requires the requesting DOCTOR and current password; POST /lab/results/:id/release requires LAB explicit intent and the latest verified version. Results carry revision, content hash, sign/verify/release actor/timestamps. Content is immutable after sign-off. GET /lab/results/:id permits LAB, requesting DOCTOR and the linked PATIENT's currently released revision only. A correction retains the prior signed/released record for audit but withholds patient access while the replacement is under review. No critical-value flags, reference-range interpretation or diagnostic recommendations are inferred.

Display manually entered tax/price information and manual external receipts explicitly. Preserve role-specific projections; never show consultation notes to OWNER, reception or LAB.
