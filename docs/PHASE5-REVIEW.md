# Phase 5 — patient portal, usage and local operations review

The user authorized Phase 5 from the Phase 4 branch. A16–A21 are implemented for local/sandbox review. This is not production activation: external vendor sandbox verification, real pricing/funding, legal/residency/retention decisions, RPO/RTO/key custody, hosting approval and independent security review remain open. No real SMS/WhatsApp, Stripe charge, public deployment or compliance certification is claimed.

## Delivered behavior

- Dormant patients request a generic activation link using the already registered facility/contact. A random, hashed, purpose/tenant/account-bound single-use proof expires after 15 minutes. Possession permits the patient to choose a four-digit PIN; staff cannot choose/view it or change the linked contact. Activation consumes the proof and invalidates old sessions/challenges. Existing verified-patient five-minute sign-in links remain supported. Email uses the existing SMTP/local adapter; mobile delivery remains local-development only and fails closed in production.
- PATIENT has a separate portal with their own linked profile, visit/ticket status, signed prescription history, lab order state/current released results and issued invoices/receipts. It exposes no staff directory, raw consultation notes or vitals, family accounts or clinical edits. Each section shows at most 100 recent records; metering is independent of that display limit.
- Private PDF generation exports explicit human-readable source fields using PDFKit and the bundled licensed DejaVu Sans font. Request retry keys bind to the authorized source; semantic uniqueness prevents duplicate copies/storage counts for an unchanged source. Files have opaque private keys, owner-only storage permissions, SHA-256 checksums and byte metadata. Failed concurrent candidates are removed. No HTML/remote URL rendering or public storage grants are exposed.
- Every PDF download authenticates and reauthorizes the linked source, verifies bytes/checksum and audits the resource ID. A withdrawn lab release becomes inaccessible even if a PDF was generated earlier; retained source revisions remain protected. Unsupported font characters return an explicit error rather than silently changing clinical content; original text remains readable through the portal. These are record copies, not external certified digital signatures.
- OWNER's monthly UTC usage view aggregates all completed-consultation events and compares them with completed encounter sources. Slabs equal ceil(count/100), with zero producing zero. New daily observations record active DOCTOR accounts and retained PDF metadata bytes once per UTC day. Reports show observed dates, coverage gaps, seat-days/seat-month and byte-days/decimal GB-month estimates. Missing history is not backfilled. Prices remain configuration placeholders, with “Pricing not configured” and charges disabled.
- The messaging wallet has immutable source-deduplicated test credits, acceptance debits and definitive-failure compensating credits. Queuing a fixed portal-access template reserves a unit against the available balance; acceptance atomically converts the reservation to a debit. Concurrency cannot overspend. Only a linked verified mobile can be used; clients cannot supply arbitrary recipients or clinical bodies. Pending bodies are encrypted and cleared on acceptance.
- MessagingProvider/BillingProvider have deterministic local adapters. Timestamped raw-body HMAC fixture callbacks resolve stored provider references into tenant scope. Event ID/reference/body-hash deduplication makes exact concurrent replays harmless, changed event bodies conflict and terminal outcomes cannot reverse. A delivery failure compensates once. A test platform bill preview requires a closed, fully observed/reconciled month and explicit rate version; no real money is collected. All test funding, provider actions and callbacks are disabled in production.
- The worker checks active tenant/current verified patient, atomically claims due jobs and backs off ambiguous adapter failures from one minute to one hour while retaining reservations. Failed or suspended jobs cannot fill the first due page forever and block newer jobs. A live adapter would additionally require provider-reference idempotency, bounded calls, consent and approved credit/cancellation rules before activation; none is configured here.
- A pinned multi-stage Docker image builds the SPA/API, prunes development dependencies, checks private-file exclusions and runs nonroot. It serves the browser/API on one site and expects a private persistent document volume, runtime secret mounts, HTTPS ingress, SMTP and a transaction-capable MongoDB. CI is configured for checks, browser journeys, image build and deployment smoke; local evidence does not claim remote CI has completed.

## Meter conventions needing production review

**ASSUMPTION - needs approval:** the first worker observation per UTC day is the sampling convention for daily clinician/storage accounting. Seat-month = observed seat-days / calendar days; GB-month = observed byte-days / calendar days / 10^9. Confirm that convention before any charging; it does not reconstruct exact historical activation intervals or unseen storage changes.

**ASSUMPTION - needs approval:** the local fixture uses one test credit per accepted message. Actual channel pricing, funding, consent and pending-reservation cancellation/expiry policies remain unset. Pending ambiguous jobs retain their reservation rather than fabricating a successful delivery or refund. There are no free production credits or zero-cost price defaults. Configured rates produce sandbox estimates only; all charging stays disabled.

## Validation record

Final local checks: **196 server tests** across ten suites, **34 UI tests** across five suites, and **3 Chromium journeys**. Phase 5 adds 25 integration/security/concurrency cases, two unit cases and six UI cases. The existing third journey now spans the clinic lifecycle through patient contact activation → PIN login → signed prescription → private PDF download → released result → receipt → reload → owner MFA/usage. Public onboarding limits are unchanged. Early browser runs found an owner-MFA test-label mismatch; it was fixed using the actual label. An initial wallet index conflict was corrected before workflow tests. A concurrency regression also exposed stale cash-close requests validating variance before version; the service now returns the documented version conflict first. No assertions were disabled.

Coverage includes all six role boundaries; patient/tenant linkage; activation generic responses, replay, expiry and session invalidation; source-bound PDF retries, simultaneous generation, byte integrity/tamper and withheld releases; unsupported text; more than 100 consultation sources, leap/UTC month boundaries, missing coverage/rates and reconciliation; credit reservation/acceptance races, one failure refund, raw signature/timestamp verification, event replay/terminal conflicts, platform-bill callback, ambiguous-send backoff and production fail-closed behavior. Audit/retry checks reject clinical/PIN/provider-body material.

Build, lint, formatting and diff checks passed. Credential scans cover Git-visible files and the final container filesystem without printing values. The dependency audit reports zero vulnerabilities. PDFKit 0.20.2 and its exact type dependency are pinned in the shared lockfile; the bundled font includes its redistribution licence.

`npm run test:backup` passed against its own disposable replica set: MongoDB archive, authenticated AES-GCM encryption, restoration into another isolated database, two synthetic tenant records/amounts, unique tenant index and tamper rejection. It cannot accept an arbitrary production restore target. This is synthetic database restoration evidence, not a scheduled/offsite production backup or object-store recovery claim.

The source Docker build passed using the same lockfile and a verified public npm cache context after Docker's direct registry access failed. TLS/integrity checks were not disabled. A private writable DOCKER_CONFIG under ignored .local handled the cloud home directory's read-only restriction. `npm run test:deployment` passed for an owned ephemeral nonroot production-mode container: frontend/SPA, database readiness, unauthenticated/API/private-file boundaries, disabled sandbox callbacks and runtime PDF/font rendering. It uses synthetic keys and an isolated database, exposes no public site and removes its own temporary container/files. Production key/volume permissions remain deployment requirements. The build excludes nested environment/local/key files; no private runtime configuration is baked into the final image.

## External gates and delivery

The implemented adapters/callback protocol are local fixtures. No actual Stripe/Twilio sandbox request or callback was possible without approved vendor accounts/test credentials. S3-compatible storage and distributed Socket.io remain future production adapter work; the current deployment is single-instance with a private persistent filesystem. No real provider delivery, payments, production storage durability or public availability is inferred from local tests.

Legal/residency/retention/deletion, tax/rates/funding, RPO/RTO and encryption-key custody, provider consent/templates/contracts and hosting still require explicit choices before activation. The synthetic archive test does not prove full MongoDB + PDF objects + managed-key disaster recovery. CodeRabbit authentication is still absent; no CodeRabbit review or issue count is claimed. Atlas/DNS was user-verified and is untouched; all tests use disposable local replica sets.
