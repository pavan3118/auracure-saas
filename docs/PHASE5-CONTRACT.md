# Phase 5 contract

This phase is authorized by the user's “phase 5” request. It implements the previously approved A16–A21 baseline in a local/sandbox configuration. Unset price/provider/legal/retention/deployment details remain activation gates, not invented production facts. No live charges, external messages or production deployment are authorized by this implementation.

Patient activation proves possession of the existing registered contact using a random single-use 15-minute activation link; the patient chooses their own four-digit PIN. Responses are generic; receptionist/owner cannot choose or see the PIN. Only previously linked dormant patients can activate; changing contact/family access remains unavailable. Email uses existing secure SMTP/local mail; mobile delivery uses the sandbox messaging interface until a real provider is configured. Existing OTP links remain single-use five-minute grants for verified patients.

GET /portal returns the linked patient's profile, own visits/status, signed prescription history, own lab order statuses/current released results and issued invoices. No raw notes/vitals/staff directory. Existing detail routes retain ownership checks. POST /portal/documents accepts kind PRESCRIPTION/LAB_RESULT/INVOICE and source_id; GET /portal/documents/:id/download reauthorizes the source every time, including withholding superseded lab releases. Private PDF objects have opaque storage keys, SHA-256 checksums and byte counts. Generation is idempotent per immutable source revision; no public storage URL is exposed. Downloads are authenticated and audited.

OWNER GET /platform/usage?month=YYYY-MM reports the four approved meters. Completed consultations aggregate all source-unique events and ceil(count/100) slabs. UTC daily snapshots record active DOCTOR count and retained PDF bytes; seat-month and GB-month estimates divide observed seat-days/byte-days by days in month (GB=10^9). Snapshots explicitly show observed dates/coverage; gaps and history before instrumentation are never fabricated. Snapshots are taken once at the first worker observation each UTC day. **ASSUMPTION - needs approval:** first-observation daily sampling refines the approved daily accounting proposal; confirm this measurement convention before any charging. Estimates remain informational and never charged. Wallet credits/debits/refunds are immutable integer units; messages reserve a configured credit, debit on provider acceptance and compensate only once on definitive failure.

Messaging and billing expose provider interfaces, a deterministic sandbox adapter and signed timestamped sandbox callbacks. Sandbox signing keys are separate environment values and never sent to the frontend. Provider references resolve stored tenant-bound resources; callback tenant_id is forbidden. Callback event IDs/payload hashes deduplicate atomically; duplicate IDs with changed content conflict. Terminal delivery/failure cannot be reverted. Stripe/Twilio remain proposed providers; local adapter tests are not external-provider certification. No price defaults or wallet free credits. OWNER may add explicitly labelled test credits only in nonproduction sandbox mode with fresh MFA. Wallet balance cannot go below zero under concurrency. Sandbox message bodies are fixed templates, never user-selected clinical text or arbitrary destinations. **ASSUMPTION - needs approval:** one fixture credit per accepted sandbox message; production channel/provider credit prices remain unset.

Deployment artifacts target a single API process with a same-site frontend, TLS ingress, transaction-capable MongoDB and private persistent storage; multiple API instances remain unsupported without shared event/object adapters. CI runs builds/lint/tests/audit; local deployment smoke and backup/restore use synthetic isolated databases. Backup artifacts contain sensitive data, must be private/encrypted and never committed. Production RPO/RTO, retention/deletion, residency, provider contracts and external sandbox credentials remain explicit pending decisions. Phase completion evidence distinguishes local checks from unavailable external gates.
