# Deployment configuration and activation gates

Build `docker build -t auracare:review .`. The image serves built client/API from one site on port 3000, runs as the node user, includes the licensed PDF font and excludes private local files. Supply runtime environment/key files through secret mounts. APP_ORIGIN must be the external HTTPS origin, SMTP_URL is required in production, MongoDB must be a transaction-capable replica set, and DOCUMENTS_DIR must be a persistent private writable mount at /data/documents. Never publish that directory or attach it to a CDN. Mount JWT/MFA/PIN keys read-only; keep the same encryption keys across restarts or encrypted records will be unreadable.

Run exactly one API instance until a shared Socket.io adapter and object store are configured and tested. Terminate TLS at the deployment platform, preserve /api and /socket.io on the same site and restrict direct API access. Trust-proxy configuration remains false: the reverse proxy's address shares pre-auth rate limits; configure only explicit trusted proxy CIDRs as separate reviewed deployment work. Production startup deliberately disables all local sandbox message/billing actions and callbacks. SMTP itself is the existing email adapter; no real WhatsApp/SMS/billing vendor is activated.

Required before production activation: hosting/country and residency approval; retention/deletion/legal requirements; RPO/RTO and backup key custody; external Stripe/Twilio suitability, contracts, test credentials and actual sandbox callbacks; explicit pricing/rate version/tax settings; production network/Atlas allow-list and least-privilege service/backup identities; object storage and cross-instance live delivery if scaling; independent security review. The image and local smoke checks do not satisfy these external gates or claim compliance.

`npm run test:backup` uses only its own disposable replica set, synthetic tenant records and private temporary directory. It verifies a MongoDB archive, authenticated encryption/tamper rejection, restoration into another isolated database, values and a unique tenant index. It cannot take an arbitrary database URI or overwrite production. Tools are extracted from the same pinned trusted MongoDB image as the test server; see scripts/prepare-backup-tools.ts. This is restoration evidence, not a scheduled production backup service. Production backups must cover MongoDB, private PDF objects and managed key versions consistently, use encrypted offsite storage and be restored in an isolated account before selecting RPO/RTO. Do not invent retention or prune clinical data without that policy.

## Restricted-network source build

If Docker's build network cannot reach npm, the same source Dockerfile supports a named public-package cache context: `docker build --build-context npm-cache=/absolute/path/to/cache --build-arg NPM_OFFLINE=true -t auracare-phase5:review .`. The cache directory must contain only npm's `_cacache` public package cache, not credentials, npmrc files or logs. npm still verifies package-lock integrity; TLS/checksum checks are never disabled. The default build stays online. Set DOCKER_CONFIG to a private writable workspace directory if the cloud home directory is read-only; this does not change application credentials.

`npm run test:deployment` starts only its own disposable replica set and temporary nonroot production-mode container from auracare-phase5:review, generates synthetic runtime keys, checks frontend/SPA/readiness/auth/API/private-file boundaries and PDF font rendering, and tears everything down. It deploys no public site. Docker build assertions reject server/.env and .local; .dockerignore also excludes nested environment/key files. Production provider callbacks remain disabled in that image.
